# Datasheet: Black-Box Optimization Capstone Data Set

## Motivation

This dataset was created to document the search process for the global optima of eight unknown black-box functions. The primary task is to support the development and evaluation of optimization strategies using limited queries (one per function per week).

The dataset serves as a benchmark for:
- Testing Bayesian Optimization algorithms
- Evaluating surrogate model performance
- Comparing acquisition function strategies
- Studying the tradeoffs between exploration and exploitation

## Composition

The dataset contains input-output pairs for eight distinct functions:

| Function | Dimensionality | Range        | Type              | Characteristics                     |
|----------|-----------------|--------------|-------------------|-------------------------------------|
| 1        | 2D              | [0, 1]^2     | Continuous        | Flat landscape, very small outputs  |
| 2        | 2D              | [0, 1]^2     | Continuous        | Gradual slope, moderate outputs     |
| 3        | 3D              | [0, 1]^3     | Continuous        | Noisy, nonlinear                    |
| 4        | 4D              | [0, 1]^4     | Continuous        | Low outputs, complex behavior       |
| 5        | 4D              | [0, 1]^4     | Continuous        | High output peaks (>7000)           |
| 6        | 5D              | [0, 1]^5     | Continuous        | Sparse signal, many flat regions    |
| 7        | 6D              | [0, 1]^6     | Continuous        | Mixed behavior, moderate complexity |
| 8        | 8D              | [0, 1]^8     | Continuous        | High-dimensional, sparse data       |

### Data Format

Each entry consists of:
- **Input Vector**: Normalized floats in [0, 1]
- **Output Scalar**: Float value (can be negative or very large)
- **Timestamp**: Week number (1-13)
- **Hyperparameters Used**: Kernel, acquisition function, beta/xi values
- **Source**: Auto-generated by optimization engine

## Collection Process

Data was collected sequentially over 13 weeks. Each week:

1. **Query Generation**: The optimization engine evaluates 16 different hyperparameter configurations per function
2. **Candidate Sampling**: Generate 1000×dimensionality random candidate points
3. **Model Training**: Fit Gaussian Process with historical data
4. **Acquisition Scoring**: Score candidates using UCB or Expected Improvement
5. **SVM Filtering**: (Weeks 3+) Filter candidates through learned decision boundary
6. **Query Selection**: Choose point with highest combined score
7. **Submission**: Submit query and record output
8. **History Update**: Add results to persistent dataframe

### Data Quality Considerations

- **Normalization**: All inputs are bounded to [0, 1]
- **Noise**: Some functions return noisy outputs (especially Functions 1, 3, 6)
- **Stability**: Function 5 shows extreme output values (>7000) requiring special handling
- **Sparse Regions**: High-dimensional functions (7, 8) have sparse data coverage

## Preprocessing and Uses

### Input Preprocessing

Inputs are converted to hashable formats (tuples) to:
- Maintain consistency across the Python optimization loop
- Detect duplicate queries
- Enable efficient caching

### Output Preprocessing

Outputs are:
- Normalized for GP training (StandardScaler)
- Logged when values are extremely small (Function 1)
- Smoothed when variance is high (Functions 1, 3)

### Intended Uses

1. **Algorithm Benchmarking**: Compare BO strategies against standard baselines
2. **Hyperparameter Tuning**: Evaluate different kernel, acquisition, and exploration settings
3. **Case Studies**: Analyze performance patterns for different dimensionalities
4. **Educational**: Learn how Bayesian Optimization works in practice
5. **Research**: Develop new acquisition functions or surrogate model types

## Limitations

1. **Limited Queries**: Only 13 total queries per function across entire project
2. **Delayed Feedback**: Results available only after weekly submission
3. **Unknown Functions**: Cannot verify function properties or ground truth
4. **Dimensionality Curse**: High-dimensional functions (7, 8) have extremely sparse coverage
5. **Non-Stationary**: Functions may have different characteristics in different regions
